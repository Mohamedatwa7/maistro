## 6.2 Moodboard — what ships (and a correction from verification)

- Visual direction: schema-validated structure from Claude (`api/_studio/mood.js`, prompt `mood-direction-v1`), palette hexes from the brand KB, the catalog look line as the only product fact, four tile briefs, competitor names rejected.
- The rendered set: ONE Soul V2 job with `batch_size 4`. **Correction (checker finding, 2026-10-21):** a Soul batch renders one prompt as variations, so the set is now rendered from a direction-level `setPrompt()` (setting, product when in the catalog, lighting, styling, palette) and every image is tagged `variation n` with `setMode: 'variations'` on the artifact. The earlier build rendered tile 1's prompt four times while tagging the images with tiles 1–4 and holding only "product" tiles to the product check — the tags claimed facets that were never asked for. The four tile briefs stay on the direction as text for the human. One job per tile (four submits) remains an option if the owner wants one image per facet.
- The product is expected in every variation exactly when the catalog has a look line (`meta.expectProduct`, explicit on the job); the vision check (`vision-check-v1.1`) stores a `stage_checks` row per set.
- Ops fixes from verification: the `vision_check` claim window is 150 s (above the 90 s call bound, so a second tick cannot re-claim a running check) and the job is patched to `running` before the call; vision `max_tokens` 8000; studio default model `claude-opus-5-5` (`MAISTRO_STUDIO_MODEL`).

## 6.6 First draft — part (b): assembly and clip checks (what ships)

| Decision | What | Why |
|---|---|---|
| Composition engine | `ffmpeg-static` bundled into the single function (`vercel.json` `includeFiles`, memory 2048 MB); `api/_studio/assemble.js` builds one filter graph: per shot trim to the exact shot duration, conform to the platform frame (scale-to-cover + crop, 30 fps, yuv420p), overlay PNG, then a chain of cuts (`concat`) or dissolves (`xfade` 0.25 s + `acrossfade`); clips without audio get synthesised silence; `loudnorm` I −14 LUFS / TP −1 / LRA 11 (builder default, platform figures unverified); H.264 veryfast CRF 20 + AAC 160k, faststart | Seedance generates clips, not edits; a deterministic composition step with numbers from ffmpeg's own probe |
| Transitions | cut, dissolve; whip / match cut / hold / none → cut (recorded as such on the result) | Honest subset; the shot list's intent is kept on the version |
| Overlays | The browser draws one PNG per shot (on-screen text upper third, caption line above the bottom safe zone; EN + AR with the browser's Arabic shaping, system-ui until the owner's typeface arrives) → `action: 'draft-overlays'` validates (8-byte PNG signature, ≤ 2 MB, shot exists) and stores them in the private bucket on `shots[n].overlay` | Text is never drawn by ffmpeg's drawtext (no shaping) nor by the image model |
| Assembly job | `action: 'draft-assemble'` (409 `prerequisites` until every clip is rendered **and approved**; 409 `busy` while one runs) queues an `assemble` job (migration 014); the tick runs it (claim window 290 s > the longest run inside the 300 s function): clips + overlays downloaded from the private bucket, assembled, the cut uploaded to `pieces/<id>/draft/cut-<job>.mp4`, the version updated through `updateShots()` with `assembled {assetPath, sha256, size, durationS, width, height, fps, loudness, transitions, overlays}`, `assetPath`/`sha256` (so QC and the legacy renderer pick it up), `variants ready`; the job's result carries the whole artifact so the page attaches it | The approval binds to the exact bytes in the bucket; nothing runs inside a request |
| Assembled checks (code) | `duration_matches_brief` (±10 %, min 0.5 s), `duration_matches_shots` (±0.35 s of the computed length), `every_shot_in_order`, `overlays_present` (every shot with text or a line has its overlay), `export_spec` (frame, 30 fps, audio) → `stage_checks` kind `spec` with the `assembled` record | The spec's "duration matches brief, every shot present in order, captions, technical specs" |
| Clip checks | On every clip attach a `clip_check` job extracts three frames (0 %, 50 %, 96 %) with ffmpeg, stores them, and runs the vision check in **clip mode** (`vision-check-v1.2`: `morphing`, `artifacts` per frame, source keyframe as the anchor, product expected per the shot); `morphing: yes` / `artifacts: yes` are hard failures, `unsure` = needs a look; stored as `stage_checks` kind `vision` with `shot`, `frames`, the probe | The spec's per-clip product-stability / artefact / keyframe-consistency checks, from real frames |
| Not yet | Logo and end-card overlay (no logo asset or rules yet — owner input 1), captions synced to a voiceover (no voiceover generation in the stack; the shot line is burnt as a caption for the shot's duration), per-platform multi-export (one export at the piece's platform frame; a second aspect is a re-assembly), licensed music beds (none available; native clip audio only) | Listed in the owner gate |



## 6.7 QC — what ships

| Decision | What | Why |
|---|---|---|
| Input bytes | `action: 'qc'` needs the draft's assembled cut (`assembled.assetPath` + `sha256`); an `f1x8_video` job on the draft stage carries `versionId` and `expectSha256`; the F1X8 adapter downloads the stored copy and **refuses to upload it when its sha256 differs** (permanent failure); `qc_results` bind to the named draft version | QC judges exactly the bytes the approval will bind to |

| Fix plan (`qc-plan-v1`, Sonnet, effort low) | One fix per F1X8 risk / failed check: `ref` (risk:N / check:code), `shot` (0 = whole piece for audio/pacing), `timestampS`, `element` (visual · overlay_text · caption · audio · pacing), `problem`, `fixType` (overlay_edit · caption_edit · audio_swap · shot_regen · shotlist_change), `instruction`, new text en/ar for text edits | The model only locates and phrases; the units are a closed list |

| Human | Approve the plan as is (Production Center; **refused with 409 `qc_stale` if the draft stage no longer holds that version or those bytes**), edit it (`qc-plan-edit`: include/exclude and re-instruct fixes → a new manual version with coverage and cost recomputed), or send back (`qc-sendback` to brief / storyboard / draft: a rejection with `details.sendBack`; an approved target is reopened by an admin, otherwise flagged) | The spec's three choices, each versioned |

Open: applying the plan is 6.8 (final); audio swaps need a licensed library (owner); the plan model is Sonnet with effort low — to be compared in 6.10.

## 6.8 Final — what ships

## 6.9 Cross-cutting — cost control (what ships)

| Requirement | What | Where |
|---|---|---|
| Estimate before every expensive generation | Every Higgsfield job is priced with `POST /estimate/<endpoint>` on the **exact body it submits** (`buildRequest()` is shared by `submit` and `estimateRequest`) before its first submit; the estimate is stored on the job (`jobs.estimate_usd`, migration 015) and returned to the page; the QC fix plan is priced the same way before anything runs (6.7). The v1 reference path has no estimate endpoint — those jobs run unpriced and are marked so | `api/_adapters/higgsfield.js`, `api/_jobs.js budgetGate()` |
| Actual cost recorded | `generation_records.cost_usd` = the estimate for a render that produced output, $0 for failed / moderated / refused renders (Higgsfield does not charge those) | `jobRecord` |
| Per-piece budget, warning, hard cap | `content_pieces.budget_usd` (default `MAISTRO_PIECE_BUDGET_USD`, builder default $25) and `budget_warn_pct` (80); spent = succeeded renders, committed = queued/running; a render that would cross the cap is **refused before submission** with the numbers; crossing the threshold puts a warning on the job; `POST /api/studio {action:'budget'}` (line manager / admin) changes it, audit-logged; `GET ?budget=` reads it; the create box shows it | `api/_handlers/studio.js`, `index.html budgetLine()` |

Hardening (checker findings): an unpriced render (v1 reference path, or a failed estimate call) is charged at the last observed estimate for its kind, else `MAISTRO_UNPRICED_USD` ($1.00), so it never escapes the cap; the estimate is **reserved on the job before** the comparison, so renders gated at the same time in different invocations count each other (the safe failure is that both are refused). The owner sets the real default budget (owner gate).

### Lineage and stage invalidation

| Rule | What |
|---|---|
| What a stage is built from | `CONSUMES` (domain): mood ← plan, thumb ← mood, brief ← mood + thumb, board ← brief + mood, draft ← board, qc ← draft, final ← qc + draft |
| Lineage | Every version records `inputs` = the current version id of each consumed stage at the moment it was recorded (migration 016) — with the shot-level references (keyframe → clip, draft → final, QC version → final) this traces a final back to its trend |
| Stale | `staleStages()` (pure, unit-tested): a stage whose recorded input is no longer that stage's current version, **or** whose input is itself stale (propagates in pipeline order); versions from before 016 carry no inputs and are never claimed stale |
| Enforcement | Approving a stale version → 409 `stale_inputs` naming the out-of-date inputs; the delivery package refuses while any stage is stale; approved stages stay immutable (an admin reopen is the only way to change one, and everything built on it then shows stale) |
| UI | `listPieces` exposes `stale` per stage; the Studio shows an "Out of date" note on the stage naming what changed |

Known window (checker note): a reopened stage keeps its version id until it is regenerated, so stages built on it read fresh until the new version lands — to be shown as "upstream reopened" later.

### Hermes parity

Every push through `POST /api/ingest` that lands in the store runs the same automated checks as a Studio artifact (`api/_studio/parity.js`): images (mood, thumbnail, storyboard sheet) are copied into the private bucket and get the 6.2 vision check (product expected on thumbnail and storyboard when the piece names one); a structured brief gets the 6.4 code checks, a legacy-shaped brief is recorded as failing "structured brief missing"; a final video is copied in and analysed by F1X8 bound to its version. When an asset cannot be copied (host outside the media allow-list, fetch failure) a **failing** check records it — a push is never silently unchecked. The response lists what was queued.
